Chapter 1 · The building block

Components

Every screen in Angular is a tree of components. A component is three things glued together by the @Component decorator: a TypeScript class (data and behaviour), an HTML template (what it looks like) and CSS (how it is styled).

What to remember

  • Selector is the custom HTML tag. Writing <app-user-card> in a parent template places this component there.
  • Standalone is the default since Angular 17. The component lists what it uses in its own imports, with no NgModule needed.
  • Inputs and outputs let a parent pass data in and listen to events coming out.
  • Lifecycle hooks let you run code at set moments. Use ngOnInit for setup and ngOnDestroy for clean-up.
user-card.component.ts
import { Component, input, output, OnInit } from '@angular/core';

@Component({
  selector: 'app-user-card',
  standalone: true,
  templateUrl: './user-card.component.html',
  styleUrl: './user-card.component.css'
})
export class UserCardComponent implements OnInit {
  name = input.required<string>();   // data in from parent
  followed = output<string>();        // event out to parent

  ngOnInit() {
    console.log('Card ready for', this.name());
  }
  follow() { this.followed.emit(this.name()); }
}
parent template
<app-user-card [name]="'Asha Rao'" (followed)="onFollow($event)" />

Interview questions

What is a component in Angular?

A component is the basic UI building block. It is a TypeScript class decorated with @Component, which supplies its metadata: a selector (the HTML tag), a template and styles. An Angular app is a tree of components starting from the root component.

What is the difference between the constructor and ngOnInit?

The constructor is a TypeScript feature that runs when the class is created. Use it only for dependency injection. ngOnInit is an Angular hook that runs once, after Angular has set the first input values. Put setup logic there, such as loading data, because inputs are available by then.

List the lifecycle hooks in order.

ngOnChanges (whenever an input changes) → ngOnInit (once) → ngDoCheck → ngAfterContentInit → ngAfterContentChecked → ngAfterViewInit → ngAfterViewChecked → ngOnDestroy (just before removal). Content hooks relate to projected <ng-content>; view hooks relate to the component's own template and children.

How do components talk to each other?

Parent to child: @Input() or input(). Child to parent: @Output() with EventEmitter, or output(). Unrelated components: a shared service (chapter 3). Parent reading a child directly: @ViewChild or viewChild().

What are standalone components?

Components that declare their own dependencies in an imports array instead of belonging to an NgModule. They were introduced in v14 and became the default in v17. Apps start with bootstrapApplication(AppComponent, appConfig).

What is view encapsulation?

It controls how component CSS is scoped. The default, Emulated, adds unique attributes so styles apply only to that component. ShadowDom uses the browser's Shadow DOM. None makes the styles global.

The four bindings

  • {{ value }} Interpolation: class → view. Shows a value as text.
  • [property]="value" Property binding: class → view. Sets a DOM or child property such as disabled, src or an input.
  • (event)="handler()" Event binding: view → class. Runs a method on click, keyup, submit and so on.
  • [(ngModel)]="value" Two-way binding: both ways. It is shorthand for [ngModel] plus (ngModelChange), nicknamed “banana in a box”.

Interview questions

What types of data binding does Angular support?

Interpolation {{ }} and property binding [ ] go from component to view. Event binding ( ) goes from view to component. Two-way binding [( )] combines a property and an event binding.

How does two-way binding work internally?

[(x)]="v" expands to [x]="v" (xChange)="v = $event". Any component with an input x and an output xChange supports it. With signals you can use model(). For form inputs, ngModel from FormsModule provides the pair.

Property binding vs attribute binding?

Property binding sets a DOM property ([value]). Some HTML attributes have no matching property, such as aria-*, colspan or data-*. For those, use attribute binding: [attr.aria-label]="label". There are also [class.active]="on" and [style.width.px]="w".

What is change detection?

It is how Angular decides when to update the view. Traditionally zone.js notices async events such as clicks, timers and HTTP calls, and Angular then re-checks bindings. ChangeDetectionStrategy.OnPush checks a component only when its inputs change, an event fires inside it, or an async pipe emits. Signals allow fine-grained, zoneless updates in newer versions.

    Why use services

    • Single responsibility: components handle the view, services handle data and business logic.
    • Share state between components that are not parent and child.
    • Reuse logic such as API calls, auth or formatting in many places.
    • Easy to test: swap a real service for a fake one in unit tests.
    cart.service.ts
    import { Injectable, signal, computed } from '@angular/core';

@Injectable({ providedIn: 'root' })   // one instance for the whole app
export class CartService {
  private items = signal<Product[]>([]);
  readonly count = computed(() => this.items().length);

  add(p: Product) { this.items.update(list => [...list, p]); }
  clear() { this.items.set([]); }
}
    header.component.ts
    export class HeaderComponent {
  cart = inject(CartService);   // same instance as everywhere else
}
// template:  Cart {{ cart.count() }}

    Interview questions

    What is a service and why use one?

    A class marked with @Injectable that holds logic or data not tied to one view. It keeps components thin, lets unrelated components share state, and centralises HTTP calls, so the code is easier to reuse and test.

    What does providedIn: 'root' mean?

    It registers the service with the root injector, so the whole app gets one shared instance (a singleton). It is also tree-shakable: if nothing injects the service, it is left out of the bundle.

    How do you share data between two sibling components?

    Put the data in a service they both inject. Expose it as a signal or as an Observable, usually through a BehaviorSubject with asObservable(), so both components react when it changes.

    Can a service have more than one instance?

    Yes. If you list it in a component's providers: [MyService], that component and its children get their own new instance. This is useful for state scoped to one screen or one widget.

    Dependency injection

    Components never write new CartService(). They ask for it, and Angular's injectors hand over an instance. If an injector doesn't have a provider, the request walks up to the parent injector until one does. Try the three requests below.

    Instances Angular created

    None yet. Angular creates an instance only when something first asks for it.

    • Press a button. AvatarComponent asks for a dependency and the request climbs the injector tree.

    How resolution works

    • Provider: tells an injector how to create something (useClass, useValue, useFactory, useExisting).
    • Injector: creates instances and caches them. Ask twice, get the same object.
    • Hierarchy: element injectors (components) are checked first, then the environment/root injector, then the NullInjector, which throws.
    • Benefit: loose coupling. Tests can provide a fake instead of the real class.

providers: [
  { provide: API_URL, useValue: 'https://api.example.com' },

    Interview questions

    What is dependency injection?

    A design pattern where a class receives its dependencies from outside instead of creating them. Angular's DI system creates, caches and supplies instances. Classes stay loosely coupled and easy to test with mocks.

    Explain the hierarchical injector.

    Angular checks the requesting component's element injector, then each parent element injector up the component tree, then the environment injectors (route injectors, then root), then the platform injector. Finally it reaches the NullInjector, which throws NullInjectorError: No provider for X. The first match wins.

    inject() vs constructor injection?

    Both give the same instance. inject() is a function you can call in field initialisers, functional guards, interceptors and factories. It also works well with inheritance. It must be called in an injection context, meaning during construction.

    What do @Optional, @Self, @SkipSelf and @Host do?

    They change the lookup. @Optional returns null instead of throwing. @Self checks only the current injector. @SkipSelf starts at the parent. @Host stops at the host component. With inject(), pass { optional: true, self: true, ... }.

    useClass vs useValue vs useFactory vs useExisting?

    useClass creates an instance of a class. useValue supplies a ready-made value such as config. useFactory runs a function to build it. useExisting aliases one token to another existing provider.

    Chapter 5 · Pages without page reloads

    Routing

    The router watches the URL, finds the first matching route in your config and shows that component inside <router-outlet>. Click the links in the fake browser and watch the route table being checked from top to bottom.

    localhost:4200/
    <router-outlet>
    app.routes.ts
    • Click a link in the fake browser. Try Admin with the box unticked, then ticked.

    The moving parts

    • Routes: an array of { path, component }, matched in order. Put '**' last.
    • routerLink: changes the URL without a full page reload.
    • <router-outlet>: the placeholder where the matched component appears.
    • Params: products/:id captures 42. Read it with ActivatedRoute or a component input.
    • Guards: canActivate can block navigation or redirect.
    • Lazy loading: loadComponent downloads a page's code only when it's visited.
    export const routes: Routes = [
  { path: '', component: HomeComponent },
  { path: 'products', component: ProductListComponent },
  { path: 'products/:id', component: ProductDetailComponent },
  { path: 'admin', canActivate: [authGuard],
    loadComponent: () => import('./admin.component')
                          .then(m => m.AdminComponent) },
  { path: 'login', component: LoginComponent },
  { path: '**', component: NotFoundComponent }
];

export const authGuard: CanActivateFn = () => {
  const auth = inject(AuthService);
  return auth.isLoggedIn() || inject(Router).parseUrl('/login');
};
    // Reading the :id parameter
export class ProductDetailComponent {
  id = inject(ActivatedRoute).snapshot.paramMap.get('id');
}

    Interview questions

    What is RouterOutlet?

    A directive that marks where the router renders the component for the active route. Child routes need their own nested <router-outlet> in the parent component's template.

    Why use routerLink instead of href?

    A plain href makes the browser reload the whole app. routerLink updates the URL with the History API and swaps only the routed component, so app state survives and navigation is instant.

    What kinds of route guards exist?

    canActivate (enter a route), canActivateChild, canDeactivate (leave a route, for example with unsaved changes), canMatch (whether the route may match at all), and resolve (load data before activating). Modern guards are plain functions that use inject().

    How does lazy loading work?

    Use loadComponent or loadChildren with a dynamic import(). The build tool splits that code into a separate chunk, which downloads only when the route is first visited. This shrinks the initial bundle.

    snapshot vs paramMap observable?

    route.snapshot.paramMap reads the value once. If the same component stays on screen while the param changes (from /products/1 to /products/2), it won't update. Subscribe to route.paramMap to react to every change, or enable withComponentInputBinding() and receive it as an input.

    Chapter 6 · Values over time

    Observables (RxJS)

    An Observable is a stream that can deliver many values over time, then complete or error. Operators in pipe() transform the stream like stations on a conveyor belt. Read this marble diagram left to right as time passes.

    source$
    pipe( filter(n => n % 2 === 0) )
    filtered
    pipe( map(n => n * 10) )
    result$

    Each circle is a next value. The black bar is complete. Crossed-out values were dropped by filter.

    • This is a finished run. Press subscribe() to play it live. An Observable does nothing until someone subscribes.

    Key ideas

    • Lazy: nothing runs until subscribe().
    • Three signals: next (a value), error and complete.
    • Operators return new Observables: map, filter, debounceTime, switchMap, catchError…
    • Unsubscribe from long-lived streams, or memory leaks. The async pipe does it for you.
    • HttpClient returns Observables that emit once and complete.
    import { interval, take, map, filter } from 'rxjs';

const source$ = interval(800).pipe(take(6), map(i => i + 1)); // 1..6

const result$ = source$.pipe(
  filter(n => n % 2 === 0),
  map(n => n * 10)
);

const sub = result$.subscribe({
  next: v => console.log('next', v),   // 20, 40, 60
  complete: () => console.log('complete')
});
sub.unsubscribe();   // stop early if needed
    real life: HTTP + async pipe
    export class ProductsComponent {
  private http = inject(HttpClient);
  products$ = this.http.get<Product[]>('/api/products');
}
    @for (p of products$ | async; track p.id) {

    Interview questions

    Observable vs Promise?

    A Promise is eager: it starts immediately, resolves once and cannot be cancelled. An Observable is lazy: it starts on subscribe, can emit many values, can be cancelled with unsubscribe(), and has operators for transforming streams.

    What are Subject, BehaviorSubject and ReplaySubject?

    A Subject is both an Observable and an Observer, so you can push values with next() and they multicast to all subscribers. BehaviorSubject needs an initial value and gives the latest value to new subscribers, which makes it good for state. ReplaySubject(n) replays the last n values to new subscribers.

    switchMap vs mergeMap vs concatMap vs exhaustMap?

    All map each value to an inner Observable. switchMap cancels the previous inner one, which suits search-as-you-type. mergeMap runs them all in parallel. concatMap runs them one after another in order. exhaustMap ignores new values while one is running, which prevents double-submitting a login.

    How do you avoid memory leaks with subscriptions?

    Prefer the async pipe in templates. In code, use takeUntilDestroyed(), or call unsubscribe() in ngOnDestroy. Streams that complete on their own, such as HTTP calls, are safe, but cleaning up is still good practice.

    Cold vs hot Observables?

    A cold Observable starts a fresh producer for each subscriber: every subscribe to an HTTP Observable makes a new request. A hot Observable shares one producer, such as mouse events or a Subject. Use share() or shareReplay() to make a cold one shared.

    Signals vs Observables?

    Signals hold a current value and are synchronous. They are ideal for UI state. Observables model events and async streams over time, such as HTTP, websockets and debounced input. Convert between them with toSignal() and toObservable().

    Chapter 7 · Trust no input

    Form validation

    With reactive forms, each input is a FormControl with validators, grouped in a FormGroup. Angular re-runs the validators on every keystroke and tracks the control's state. Type in the form and watch the inspector on the right change live.

    Live form state

    What the inspector shows

    • status: VALID or INVALID (also PENDING for async validators, and DISABLED).
    • touched / untouched: whether the user has left the field (blur).
    • dirty / pristine: whether the user has changed the value.
    • errors: an object such as { required: true }, or null when valid.
    • Show messages only when invalid && (touched || dirty), so you don't shout at users before they type.
    export class SignupComponent {
  private fb = inject(FormBuilder);

  form = this.fb.group({
    name:     ['', [Validators.required, Validators.minLength(3)]],
    email:    ['', [Validators.required, Validators.email]],
    password: ['', [Validators.required, Validators.minLength(8), hasNumber]],
    confirm:  ['', Validators.required]
  }, { validators: passwordsMatch });   // cross-field rule

  submit() {
    if (this.form.invalid) { this.form.markAllAsTouched(); return; }
    console.log(this.form.value);
  }
}

// custom validator: returns null when valid
export const hasNumber: ValidatorFn = c =>
  /\d/.test(c.value) ? null : { noNumber: true };
    <form [formGroup]="form" (ngSubmit)="submit()">
  <input formControlName="email" />
  @if (form.controls.email.touched && form.controls.email.hasError('email')) {
    <small>Enter a valid email address</small>
  }
  <button [disabled]="form.invalid">Create account</button>
</form>

    Interview questions

    Template-driven vs reactive forms?

    Template-driven forms (FormsModule, ngModel) define the form in HTML. They are quick for simple forms, but logic is spread across the template. Reactive forms (ReactiveFormsModule) define the form model in TypeScript. They are explicit, synchronous, strongly typed and easier to unit test, so they are preferred for complex forms.

    Which built-in validators exist?

    required, requiredTrue, minLength, maxLength, min, max, email, pattern, plus Validators.compose to combine them.

    How do you write a custom or cross-field validator?

    A validator is a function (control) => ValidationErrors | null. For cross-field rules such as matching passwords, attach it to the FormGroup so it can read sibling controls. Async validators return an Observable or a Promise, and the status becomes PENDING while they run.

    setValue vs patchValue?

    setValue needs a value for every control in the group and throws otherwise. patchValue updates only the keys you pass. Both trigger validation unless you pass { emitEvent: false }.

    How do you validate only when the user leaves a field?

    Set updateOn: 'blur' on the control or group, for example this.fb.control('', { validators: [...], updateOn: 'blur' }). Use 'submit' to validate only on submit.
